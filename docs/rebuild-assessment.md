## 再構築方針

### 技術選定

React + TypeScript + Vite、CSS、純粋reducer、localStorage、Vitest/Playwrightを継続する。DOMで扱える規模で、ゲームエンジン、状態管理ライブラリ、バックエンドを追加する根拠はない。全面書換えを避け、判定と描画の契約を修復する。

### 世界観辞書と画面構成

- 世界観: 絵本の旅。空・森・虹・川辺・夜空、白い盤面枠、木の線路、クリーム色のレール置き場。
- HUD: コース名・星・戻る。ゲーム盤面の上辺、横長時は盤面右側の操作列に配置する。
- ターゲット: 点線の穴。選択カードは暖色の枠、配置済みカードは同じ位置で状態を示す。正解の形を先に教える新機能は追加しない。
- 文言: 「レールをえらんでね」「あなをタップしてね」「クリア！」など、現在可能な操作を短く案内する。既存の失敗・成功文言は維持。
- エフェクト・画像: 既存画像と控えめな影を使用。画像生成は候補として検討したが、既存の世界観を変える必要がないため今回は使わない。
- アンカー: 線路・穴・電車は共通surface内。HUDとトレイはCSS Gridの別領域。固定の画面比率による重なりを作らない。
- 内部寸法: トレイは候補の画像・ラベル・padding・gapから高さが決まる。結果panelは内容高を基準にし、画面より高い場合は内部スクロールする。

### 対象と非対象

対象は既存仕様の不具合、軽微な操作案内、レスポンシブ、対象回帰テスト、互換性を確認した依存更新、README/docs同期。

非対象は新電車・新コース、候補のランダム化、速度やリトライ方式変更、音声/PWA追加、アカウント、外部API、保存形式変更、アセット削除、全面移行。push/PR/merge/deployは今回行わない。

### 実装計画

1. 旧版コピーで比較基準を確保し、要件・観測を記録する。
2. 通過済みレールの不変条件を回帰テストで再現し、reducerと操作表示を修正する。
3. 共通surface、内容に応じたトレイ、結果panelの収まりを実装する。
4. 短い操作案内とクリア済表示を追加し、保存契約を維持する。
5. 実際の依存監査に基づいて限定更新する。破壊的更新が必要ならその部分を別判断にする。
6. 対象テスト、ビルド、代表画面、主要フローを比較し、READMEと実行結果を追記する。

### 受け入れ条件

- 15コースと既存保存データを維持し、正解・不正解・二種リトライ・解放が動く。
- 到達前は戻す・再配置でき、通過後は返却・移動・上書きできない。
- 電車の座標と線路のマス中心が同じsurfaceから算出される。
- 390×844、768×1024、844×390、1280×720で盤面と操作欄を測定し、穴が重ならない。小さい画面でも縮小で操作不能にせずスクロールを許す。
- 結果panelの全ボタンへ到達でき、下端・右端の収まりを実測する。
- 配置後も残り候補の位置が変わらず、案内と操作可否が一致する。
- ブラウザでクリア、次コース、再読み込み後の解放維持を確認する。

### 性能目標

- 新たな外部ランタイム依存や画像を増やさない。静的配布サイズを不必要に増加させない。
- レール配置は操作直後の描画に反映する。人工的な待ち時間を追加しない。
- 電車更新頻度・コース速度を維持する。物理端末のFPS、入力遅延を未測定のまま数値保証しない。

### リスクと対策

| リスク | 対策 |
|---|---|
| 通過済み固定がチェックポイント再開を壊す | 通過済みと失敗穴を分けてreducerテスト |
| 高密度トレイの文字切れ・タップ領域縮小 | 5穴の代表画面と横向きで実寸測定 |
| 保存互換性 | 保存キー・ID・解放ロジック不変、再読み込み確認 |
| 依存更新の破壊的影響 | lockfile差分を確認し、テスト・build・E2Eを更新後実行 |
| 自動テスト成功が子供の理解を保証しない | 物理iPad・3歳児の理解度は未確認と明記 |

最終確認: 受け入れ条件・非対象・リスクと対策・性能目標を上記に保持する。
