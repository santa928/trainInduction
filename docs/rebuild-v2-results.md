# Three.js再構築の検証記録（2026-10-22）

対象は `rebuild/threejs-complete`。比較元は `d7fe410812c9f0e56f6abf49896219630fa5d89e`。

## 既存版の調査

README、既存コード、`docs/rebuild-assessment.md` と公開版を照合した。公開JS/CSSのSHA-256は比較元のローカルビルドと一致した。クラウドChromiumの直接TLS接続は失敗したため、システムCAで検証して取得した同一の公開資産をブラウザへ渡して操作した。

評価資料の「変更前の観測」を現行の不具合とは扱わない。通過した穴の固定、候補位置の保持、4画面サイズでの穴の非重複、結果画面の収まりは現行版ですでに修正されていた。実時間で1面目の置き直し→通過後ロック→到着→次面解放→再読込で保持、および未配置失敗→リトライを確認した。一方、3電車で同じ5経路を共有し、候補が正解到達順に生成される点、非表示時の時計停止がない点はコードでも確認した。新しい設計では前者の構成を変更し、停止も追加した。

比較元のDockerビルドと60件の単体/コンポーネントテストは成功した。[調査記録](rebuild-v2/evidence/baseline-summary.json)を保持する。

## 完成版の変更

- 時間制限を維持。3秒準備→自動走行→未配置/誤配置の手前で失敗→全配置をリセットして再挑戦。
- 3電車・共通12面。位置ずらしを除いた経路の重複なし。形・向き・連続する穴と有限ピースの組合せへ進む。
- Three.jsの玩具ジオラマ。線路と列車が同じ曲線関数を使い、向き・車輪・減速・煙・旗・紙吹雪を描画。
- タップ選択→穴への配置、タッチドラッグと取消、返却/上書き。候補は開始時に並べ替え、操作/リトライ中は位置を維持。
- 正誤は列車到達時に判定。配置時の正解表示や誤答候補の自動除去なし。ステージ選択も答えを示さない駅のイラスト。
- 非表示/フォーカス喪失/描画コンテキスト喪失で停止し、明示再開。音量切替、動きを減らす設定、WebGL再試行。
- 旧保存キー・旧素材・旧ロジックを保持。新形式は別キーで保存し、旧到達段階を解放へ移行。別内容の新面をクリア扱いにはしない。

## ブラウザ検証ログの対応

修正に応じた分割実行と再実行で確認した。単一の全件成功ログではない。途中の失敗はログにも残している。画像/DOMトレースによる入力遅延、短い画面での重なり、停止中の時計混入を調べ、描画と時計の不具合を修正し、検証の記録負荷も取り除いた。時計の速度を落としたり、正解配置・クリア状態を直接注入したりして通してはいない。

## 実操作と画像

配布用ZIPを展開してHTTPで配信し、ビルド時のSHA-256と4ファイルの一致を確認した。Chromiumの390×844、Playwrightの実タッチ入力を使用し、12面目へES/EW/WN/EW/NEの5ピースを2タップ操作で配置。走行中に844×390、768×1024、1280×720へ変更し、実時間で駅到着まで確認した。保存fixtureは後半面の解放だけに使用し、配置やクリア状態を直接書き込んでいない。自動時計は使用していない。途中で実際の停止ボタンを押し、距離が変わらないことと明示再開も確認した。

別セッションでPCのマウスによる配置→返却→未配置失敗を確認し、短い390×664画面を撮影した。記録用の撮影・DOM読み取りの負荷も制限時間を消費するため、短い画面の撮影は完走操作とは分けた。物理端末で指を使って確認した、という意味ではない。[ZIPのハッシュ](rebuild-v2/evidence/review-build.json)、[12面の実操作ログ](rebuild-v2/evidence/train-v2-production.log)、[別セッションの操作ログ](rebuild-v2/evidence/train-v2-production-extras.log)を残す。12面の脚本は到着確認後に同名メニューボタンのstrict locatorエラーで止まったため、後続のメニュー/PC操作はdialog内のボタンを選んで再確認した。

## レビューで修正した事項

独立したコードレビューの指摘に加え、実操作・追加検証で見つかった事項も再現テストで確認して修正した。

1. カメラ変更時に古い行列で穴を投影していた → world行列を更新してから投影。
2. 直線だけの停止余白では曲がったバンパーが未接続マスへ入り得た → 曲線時の車体幅も含む余白と、実モデルの全穴境界テスト。
3. ステージ選択に最初の穴の正解が描かれていた → 接続形状に関係ない駅のイラスト。
4. 7面目と9面目が位置ずらしだった → 9面目を別経路へ変更し、正規化後の重複検査。
5. PCの傾いた視点、およびWebKitの390×664画面で入力領域が少し重なっていた → 最小44pxを保って領域を調整。短い盤面は真上寄りの視点とし、投影矩形の非重複テストを追加。
6. 12面目に別の物理的な接続経路ができた → 全ピース割当を実際の端点接続で歩く検査を追加し、紛らわしい余剰ピースを変更。正規経路以外が駅へつながる配置を排除。
7. フレームが来ない間の停止→再開で、停止中の時間が次の走行deltaへ混ざり得た → 停止状態が変わるとフレーム時計の基準をリセット。60秒停止後の最初のdeltaが0になる回帰テストを追加。プレイ中の実際の遅延は時間として数えることも同じテストで確認。

## 確認の限界

- LinuxのソフトウェアGPU（SwiftShader）による検証。実機iPhone/iPadのFPS・発熱・メモリ、Safari実機でのタッチ/復帰は未確認。
- 音の生成とミュート経路は実装したが、端末スピーカーでの実聴は未確認。音声品質を自動テスト済みとはしない。
- 3歳児本人の理解度や難易度の受け入れは未確認。到達前の時間、候補数、後半の連続穴は実機プレイで調整する余地がある。
- ソフトウェアWebGLでの並列実行とトレース画像の記録が入力を遅延させたため、1 worker・トレース無効で検証した。DOMスナップショットも1操作約1秒の遅延を生んだため無効化し、失敗ログと静止画を保持する。ゲームの時計・列車速度を緩めて回避してはいない。
